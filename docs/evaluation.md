## 真實 Gmail 整合試跑

日期：2026-10-11。使用者授權連接測試信箱並開始處理。先核對工具的帳號身分，再讀取 20 封收件匣郵件；只依內容判斷，不以 Gmail 的自動分類取代判斷。

- 3 封已確認純促銷移到垃圾桶。
- 10 封保留並分類封存，包含通知、帳單、發票及使用者主動徵求的商品到貨資訊。
- 6 封有待辦／安全待確認事項，分類後保留收件匣。
- 1 封正文編碼異常，保留收件匣待判讀。

新增 3 個有實際用途的分類，其他沿用既有標籤。封存使用單封郵件移除 INBOX，避免影響整個討論串；完成後重新讀取全部 20 封，核對標籤、收件匣／垃圾桶狀態及已讀／未讀狀態，全部符合預定處置且已讀狀態保持原樣。操作後也重新取得收件匣實際計數。

這次只覆蓋一個帳號與一批正常成功操作，未驗證整個信箱、大量批次、部分失敗及逾時重試。帳號地址、真實郵件 ID、原文、憑證及私人紀錄均未收入公開套件。

## 一次啟動版執行器驗證

日期：2026-10-11。新增 JavaScript 執行器、Codex 工具橋接與 Python 原子進度儲存。20 項測試通過：18 項合成 Gmail 行為測試、2 項真實本地檔案儲存整合測試。

- 231 封合成郵件完整分頁、25 封分批、先標籤再封存、保留未讀狀態。
- 帳號不符、缺少人類授權、月報、證券日報、付款憑證與已購課程阻擋不合規修改；預覽不修改。
- 操作逾時後查實際狀態、部分成功後續跑、前組失敗不消耗後組重試次數。
- 執行期間人工刪除／還原、重新加入收件匣與 history 變動保留為例外；缺 history 的模糊續跑不自動修改，權限錯誤停止後續修改。
- 最後查核能辨識漏封存、重要信消失、垃圾桶郵件被還原、分類標籤被移除及新來信。
- 62 筆私人進度切片重新載入；特殊字元不進入 shell 執行；損壞的暫存 JSON 不覆蓋有效紀錄；最終檔案權限 0600。

真實 Gmail 只讀檢查核對指定帳號，取得當時收件匣 93 封、未讀 37 封，保存並重新載入同一份 93 封清單。修改 adapter 被強制禁止，實際郵件修改數為 0；只讀清單尚未逐封分類，狀態正確為 needs_review。公開套件不含該帳號、郵件 ID 或私人進度。

初版的一批真實修改試跑不能替代新版整輪驗證。新版尚未在真實信箱測試大量修改、真實中斷恢復或長期排程；模型內容判斷也沒有準確率保證。

新版非啟用的安裝草稿已通過 Ruby YAML、UI 字串、JSON 與 Skill 內部文件連結檢查。嘗試系統 `quick_validate.py` 時，隨附 Python 仍缺少 PyYAML，因此未宣稱該驗證器通過。
